## 2. สองเส้นทางที่ทำให้จอประกาศ — เกณฑ์นี้พูดถึงเส้นทางที่สองเท่านั้น

สเปก §4 เขียนไว้เองว่าจอประกาศเมื่อ **(ก)** มีเลขใหม่เข้า serving **หรือ (ข)** serving order
ตัวเดิมมี `announcedAt` เพิ่มขึ้น เกณฑ์ข้อนี้คือ **(ข)**

`newlyAnnounced()` ถือว่าเลขที่ **ไม่มีใน snapshot ก่อนหน้า** เป็นของใหม่เสมอ (`was === undefined`)
→ เทสต์ระดับจอที่เผลอปล่อยให้เลขหายจาก serving แล้วกลับมา จะ **เขียวผ่านเส้นทาง (ก)
โดยไม่ได้พิสูจน์อะไรเกี่ยวกับ `announcedAt` เลย** (รอบ 0002 พิสูจน์ปรากฏการณ์นี้ไปแล้วด้วย M5
ของรอบนั้น: ลบ `announcedAt` ออกจาก `recall()` แล้วเทสต์ฝั่ง Display ยังเขียวหมด)

**วิธีที่ไฟล์นี้ปิดทางที่ไม่ใช่**: ทุกเทสต์ระดับจอ (section D) ใช้ **id เดิม เลขเดิม อยู่ใน serving
ทั้งก่อนและหลัง** และ assert ว่ามันไม่เคยหายไปจากโซน serving (`getAllByTestId('serving')`)
mutation M4 (ทำให้ `newlyAnnounced` คืนเฉพาะ `was === undefined` = ตัดเส้นทาง ข ทิ้ง)
ฆ่า D1·D3·D4·D5·D6 ครบ → ยืนยันว่าไฟล์นี้ยืนอยู่บนเส้นทาง (ข) จริง

### การตัดสินที่บันทึกไว้

1. **"สำหรับเลขนั้น" พิสูจน์ได้ถึงระดับไหน** — พิสูจน์ได้จริงที่ **ตัวเลือก** (C1: `newlyAnnounced`
   คืนเฉพาะเลขที่ถูก bump) และที่ **พาเนล** (B4: เขียนเฉพาะใบที่กด) แต่ **พิสูจน์กับตัว flash ไม่ได้**
   เพราะ flash เป็น class บน **root ของทั้งจอ** ไม่ได้ผูกกับเลขใดเลขหนึ่งโดยโครงสร้าง
   → **ไม่มีเทสต์ตัวไหนแกล้งทำเป็นพิสูจน์** และ D5 เขียนข้อเท็จจริงนี้ไว้ตรงๆ ว่าดังครั้งเดียวทั้งจอ
2. **`announcedAt` ที่ลดลงต้องไม่ประกาศ** — `newlyAnnounced` ใช้ `>` ไม่ใช่ `!==` ซึ่งเป็น
   การตัดสินใจจริงในโค้ด: snapshot ไม่ได้มาเรียงเวลา (offline sync / นาฬิกาสองเครื่องเพี้ยน)
   จอลูกค้าต้องไม่ประกาศย้อนหลัง — เดิม **ไม่มีเทสต์ตัวไหนในรีโปล็อกข้อนี้** (M3 ยืนยัน)
3. **guard ของ `reannounce` ไปไม่ถึงจาก UI** — ปุ่ม render เฉพาะการ์ด serving (B3) → guard (A2)
   เป็น defence ชั้นสอง เหมือนกรณี `callSpecific` รอบ 0031 **ล็อกทั้งสองชั้น ไม่เดาว่าชั้นไหนพอ**

## 7. สิ่งที่ตรวจแล้วตัดสินว่า **ไม่ใช่** ช่องว่าง (บันทึกไว้ ไม่ปล่อยเป็นสถานะ "ไม่รู้")

1. **กดสองครั้งในมิลลิวินาทีเดียวกัน = ไม่มีการประกาศครั้งที่สอง** (`Date.now()` เท่ากัน →
   `announcedAt` ไม่เพิ่ม → `>` เป็นเท็จ) มนุษย์กดปุ่มสองครั้งห่างกันต่ำกว่า 1 ms ไม่ได้
   **ไม่แก้** และการ "แก้" ด้วย `Math.max(prev+1, now)` จะทำให้ timestamp ไม่ใช่เวลาจริงอีกต่อไป
2. **`announcedAt ?? 0` ที่ `DisplayScreen.tsx:26`** ทำให้ order ที่ **ไม่เคยถูกประกาศ** กับ order
   ที่ประกาศตอน epoch 0 แยกกันไม่ออก — วันนี้ไปไม่ถึง เพราะทุกทางที่ทำให้ order เข้า `serving`
   (`callNext` · `callSpecific` · `recall`) เซ็ต `announcedAt` เสมอ **ไม่แก้** (จะกลายเป็น
   การเปลี่ยน logic โดยไม่มีเกณฑ์ไหนเรียกร้อง)
3. **`orderSnapshot()` ฉบับที่มีบั๊ก** (คัดลอกเฉพาะ field ที่ `!== undefined`) ยังอยู่บน branch นี้
   รอบ 0053 แก้ไปแล้ว **บน branch อื่นที่ไม่เคย merge** — เป็นเกณฑ์ Undo คนละข้อ
   **จงใจไม่แตะ** เพราะจะชนกับงาน `_0053` ตอน merge
4. **`shadow-[0_0_40px_rgba(...)]` (`:75`) และ `glow-y` (`:84`)** ที่รอบ 0051 ตัดสินว่าเป็นบั๊ก
   Neon Clarity ก็ยังอยู่บน branch นี้ด้วยเหตุผลเดียวกัน — คนละเกณฑ์ **จงใจไม่แตะ**
