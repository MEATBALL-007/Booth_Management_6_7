## 3. การตัดสินใจสองข้อ และเหตุผล

### 3.1 ทำไมเป็น `px` ไม่ใช่ `rem`

`index.css` ตั้ง `html { font-size: 120% }` → root = **19.2px**
ถ้าประกาศ radius เป็น rem ตัวเลขที่เรนเดอร์จะ **สูงกว่าสเปก 20%** (10px → 12px)

สเปก §2 เขียนแยกกันสองบรรทัด:
- บรรทัด radius ระบุหน่วยเป็น **px ตรงตัว** (`sm 10px · md 14px · lg 16px · xl 20px`)
- บรรทัด base scale ระบุขอบเขตไว้ว่า **`ตัวหนังสือ/ปุ่ม/สเปซ/ตัวเลข`** — **ไม่มีมุมโค้ง**

📌 **`neonClarity B2` เห็นด้วยกับการอ่านนี้อยู่แล้ว** — มันห้าม px ใน
`fontSize` / `spacing` / `lineHeight` (สเกลที่ *ต้อง* โตตาม root) และ **ไม่รวม `borderRadius`**
รอบนี้จึง **ไม่เพิ่ม `borderRadius` เข้าลิสต์ที่ห้าม** และเขียนเหตุผลไว้ในเทสต์แล้ว

### 3.2 ทำไม *ไม่* แก้ inversion ที่ตัวเองสร้าง

🚨 **ผลข้างเคียงจริงของการ override: สเกลกลับหัวที่รอยต่อ**

สเปกมี 4 ขั้น (`sm md lg xl`) แต่ Tailwind มี 9 ขั้น พอดัน `xl` ขึ้นเป็น 20px
มันจึง **แซง `2xl` ที่ไม่ได้แตะ** (`1rem` = 19.2px ที่ root นี้)

```
xl  = 20px      ← สเปกกำหนด
2xl = 19.2px    ← Tailwind default, สเปกไม่ได้พูดถึง
➡️ rounded-xl มนกว่า rounded-2xl
```

**และมันไม่ใช่เรื่องสมมติ — ทั้งสองขั้นอยู่บนจอจริง** (`xl` 6 ที่ · `2xl` 8 ที่)
การ์ด 8 ใบที่ขอมุมมนกว่าเพื่อนบ้าน ตอนนี้ได้มุมที่ **เหลี่ยมกว่า**

**ไม่แก้รอบนี้ และเหตุผลคือ:** สเปก **ไม่ได้ให้ค่า `2xl`/`3xl`** ไว้เลย
ทางแก้ทุกทางจึงเป็นอย่างใดอย่างหนึ่ง — **เดาตัวเลขขึ้นมาเอง** หรือ
**ไล่แก้ call site 8 ที่จาก `rounded-2xl` เป็น `rounded-xl`** ซึ่งเปลี่ยนหน้าตาการ์ดทุกใบ
ทั้งสองอย่างเป็น **การตัดสินใจเชิงดีไซน์ ไม่ใช่การ audit** และรอบนี้ถูกกำหนดขอบเขตไว้ว่า
"ประกาศ token ที่ §2 ระบุ"

➡️ **`G0` ปักมันไว้แทน** ทรงเดียวกับ `idempotency E1` · `pwa I1` · `alert C5` · `donation T1–T3`
**ถ้าวันหนึ่ง G0 แดง = มีคนตัดสินใจแล้ว นั่นคือการแก้ ไม่ใช่การถดถอย**

## 4. คอลลาเทอรัลที่ทำนายไว้ก่อนแก้ — และผลจริง

handoff ของ `_0005` เตือนไว้ว่าแก้ `tailwind.config.js` จะทำ `frozenZones C1` แดง
**ทำนายไว้ 4 ไฟล์ที่อ่าน config · ตรง 4 จาก 4**

| audit | ทำนาย | จริง | เหตุผล |
|---|---|---|---|
| `frozenZones C1` | 🔴 | 🔴 | `classify()` ไม่มีหมวด config → `'unknown'` |
| `frozenZones P1` | 🟢 | 🟢 | config ได้ `'unknown'` ไม่ใช่ `'production'` |
| `neonClarity B2` | 🔴 | 🔴 | canary ปัก `extendKeys` ไว้เป๊ะ 3 ตัว |
| `uiOverhaulDiffScope T0/T1` | 🟢 | 🟢 | มีหมวด `style-config` อยู่แล้ว |
| `responsiveTouchTargets R0` | 🟢 | 🟢 | ตรวจแค่ว่าไม่มี `screens:` |

### วิธีซ่อม — **ทั้งสองที่ซ่อมโดย *รัด* ไม่ใช่ *คลาย***

**`frozenZones`** — handoff สั่งว่า "ทางแก้คือ *เพิ่ม* หมวด config ห้ามคลายกฎ"
แต่ **การเพิ่มหมวดเปล่าๆ คือการคลายกฎในอีกรูปแบบ**: พอ config ไม่ใช่ `'unknown'` แล้ว
**ไม่มีอะไรเฝ้ามันอีกเลย** จึงเพิ่มเป็น **หมวดที่ต้องประกาศ** แบบเดียวกับ `PRODUCTION_CHANGES`:

- `classify()` เพิ่มกฎ **แคบมาก** — แมตช์แค่ `tailwind|postcss` เท่านั้น
  `package.json` · `vite.config.ts` · `tsconfig.json` **ยังเป็น `'unknown'` และยังทำ C1 แดง**
  (C0 ปักทั้งสามไว้แล้ว เพื่อไม่ให้กฎนี้กลายเป็น "ไฟล์ config อะไรก็ผ่าน")
- เพิ่ม `CONFIG_CHANGES` + เทสต์ใหม่ **`C2`** — config ที่เปลี่ยนต้องมีเหตุผลกำกับ
  **การเป็นหมวด ไม่ใช่ใบอนุญาต**

**`neonClarity B2`** — canary ตัวนี้ **เขียนไว้รอรอบนี้โดยเฉพาะ**
(`"When a round adds a scale here, this fires and forces the check below to be re-read"`)
จึงอัปเดต array เป็น 4 ตัว **แล้วอ่านกฎข้างล่างจริงตามที่มันสั่ง** และบันทึกว่า
**ไม่เพิ่ม `borderRadius` เข้าลิสต์ห้าม px** พร้อมเหตุผล (§3.1)
