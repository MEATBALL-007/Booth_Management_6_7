## 2. ทำไม 19.2px

`src/index.css:5` → `html { font-size: 120% }` → `16 × 1.2 = 19.2px`
(`neonClarity` B1 พิสูจน์ตัวเลข 120% นี้ไว้แล้ว ไฟล์นี้อ้างอิง ไม่พิสูจน์ซ้ำ)

ผลที่ตามมาซึ่งเป็นหัวใจของ T4: **utility ที่เป็น rem โตตาม root · `[44px]` ไม่โต**
`py-3` = 28.8px (โตจาก 24) แต่ `min-h-[44px]` = 44px เท่าเดิมตลอด
ถ้าเขียน `h-11` (2.75rem) จะได้ **52.8px ไม่ใช่ 44** — คนละของกัน

เกณฑ์เขียนว่า "≥44px" เฉยๆ ไฟล์นี้อ่านแบบ **CSS px ตรงตัว** ซึ่งเป็นการอ้างที่อ่อนกว่า
ถ้าเจตนาจริงคือ "44px หลังสเกล" (= 52.8) ทุกปุ่มยังผ่านอยู่ดีเพราะ line-height พาไป
แต่ **หลักประกันที่ประกาศไว้จะไม่พอ** — เป็นคำถามที่ต้องให้คนตัดสิน ไม่ใช่เทสต์

## 3. สิ่งที่ **ไม่ได้** พิสูจน์ (อ่านก่อนเชื่อไฟล์นี้)

🚨 **ไม่มีพิกเซลไหนถูกวัด ไม่มี viewport ไหนถูกตั้ง ไม่มี stylesheet ไหนถูกประเมิน**
jsdom ไม่ทำ layout — `scrollWidth > clientWidth` คือ `0 > 0` = false เสมอ
เทสต์ที่เขียนแบบนั้น **เขียวกับทุกโค้ดเบสที่เป็นไปได้** ไฟล์นี้จึงไม่เรนเดอร์อะไรเลย

- **ไม่ได้พิสูจน์ว่าไม่มี horizontal scroll** — กลุ่ม X เป็น **census ของ *สาเหตุ***
  (ความกว้างตายตัวที่กว้างกว่าจอ · grid track ที่ไม่ใช่เศษส่วน · scroller ที่กลบปัญหา)
  ข้อความยาวเกิน ฟอนต์กว้างกว่าที่คิด หรือรูปที่มีขนาดในตัว **ล้นได้โดยไม่มี assertion ไหนแดง**
  นี่คือ proxy และถูกเรียกว่า proxy
- **ไม่ได้พิสูจน์ความกว้างของ touch target ทั่วไป** — T5 สวีปเฉพาะปุ่มที่ป้ายเป็นอักขระเดียว
  (`−` / `+`) ซึ่งเป็นตัวที่ padding *คือ* ความกว้าง ตัวอื่นรับความกว้างจาก container
  (`w-full` / `flex-1` / grid track) การใส่ min-w ให้มันจึงไม่ใช่เงื่อนไขที่ผูกพัน
  **นี่คือการตัดสินใจ ไม่ใช่การวัด**
- **ปุ่มที่ body เป็น JSX expression ถูกยกเว้นจาก T5** (`{L('queue.done').th}`) — อ่านป้ายไม่ได้
- **`minmax(0,1fr)` ของ Tailwind เป็นสมมติฐาน** — X4 อาศัยว่า `grid-cols-2` แปลเป็น
  `repeat(2, minmax(0,1fr))` ตามเอกสาร ซึ่งคือเหตุผลที่ 2 คอลัมน์บนมือถือไม่ทำให้ล้น
  **Tailwind ไม่เคยรันในเทสต์นี้**
- **"อ่านง่าย" ไม่ได้ถูกทดสอบ และไม่ได้อ้าง** — ควรมีคนเปิดดูจริงทั้งสี่ความกว้าง

## 6. บั๊กในตัวเทสต์เองที่เจอระหว่างทาง

รอบแรกที่รัน มีแดง 4 ตัว: T3/T4 (ช่องว่างจริง) **บวก C0 กับ R4 ซึ่งเป็นบั๊กของ checker เอง**

`classTokens` เวอร์ชันแรกจับ template literal ด้วย ``/`([^`]*)`/`` แล้วเอา **ข้อความดิบทั้งก้อน**
รวม `${active ? '…' : '…'}` มาเป็นคลาส ผลคือ token หน้าตาแบบ `active`, `?`, `:`
โผล่เข้ามา และ `splitVariant(':')` คืน prefix ว่าง → R4 รายงานมันเป็น prefix ที่ไม่รู้จัก

แต่ **อาการที่มองไม่เห็นสำคัญกว่า**: คลาสที่อยู่ *ในสองกิ่งของ ternary* จะกลายเป็น
token ที่มีเครื่องหมายคำพูดติดอยู่ (`"min-h-[44px]"`) → **แมตช์ไม่โดน → นับไม่เข้า**
ซึ่งแปลว่าสถานะ active/inactive ของทุกปุ่มในแอปนี้จะหายไปจากเลขคณิตแบบเงียบๆ
สวีปที่ tokenize ผิดไม่พังเสียงดัง มัน **นับขาด** ซึ่งคือทิศทางที่ทำให้เขียวฟรี

แก้ด้วย `templateClasses()` ที่แยกส่วนนอก `${…}` ออกจากสตริงที่อยู่ข้างใน แล้ว recurse
C0 ปัก fixture ที่มี ternary ไว้โดยเฉพาะเพราะเรื่องนี้ (M11 วัดว่ามันคือด่านจริง)
