## 1. ตัดสินขอบเขตของเกณฑ์ก่อน (ไม่เดา — บังคับด้วยตัวสเปกเอง)

เกณฑ์บรรทัดเดียวนี้มี **3 ข้ออ้างซ่อนอยู่** และข้อที่ 3 กำกวมจริง จึงต้องตัดสิน:

| # | ข้ออ้าง | ตัดสินอย่างไร |
|---|---|---|
| 1 | เปิดพร้อมกันสองเครื่อง | ตรงตัว — render `DashboardScreen` สองครั้ง คนละ deviceId |
| 2 | เห็นข้อมูลตรงกัน realtime | ยิง snapshot ชุดเดียวเข้า listener ทั้งสอง แล้วเทียบทุกช่องบนจอ |
| 3 | ปิดเครื่องนึง อีกเครื่องทำงานครบ | **กินทั้งสองความหมาย** (ดูข้างล่าง) |

**"ปิดเครื่อง" มีสองความหมาย และตัดสินว่าเกณฑ์กินทั้งคู่:**

- **(ก) ปิดหน้าต่าง/ปิดเครื่อง** → อีกเครื่องต้องรับ snapshot ต่อได้ และยัง "ทำงานครบ"
  คำว่า "ครบ" ไม่ได้เดาเอง — **§4.1 `:98` นิยามไว้ตรงตัว**:
  *"2 เครื่องเหมือนกันทุกปุ่ม (ทั้งคู่ view + export + broadcast + control ได้ครบ)"*
- **(ข) เครื่องนั้นหลุดเน็ต** → HQ อีกเครื่องต้องเห็นเป็น "หลุด"
  **§5 `:157` เขียนไว้เองตรงตัว**: *"presence heartbeat หยุดตอน offline → HQ เห็นเป็น 'หลุด' ถูกต้อง"*

**บรรทัด `:157` คือตัวชี้ขาด** — ถ้าเกณฑ์กินแค่ (ก) จะไม่มีเกณฑ์ข้อไหนในสเปกทั้งใบรับผิดชอบข้อ (ข) เลย
ทั้งที่ตัวบรรทัดนั้นพูดถึง HQ โดยตรง → อ่านเป็น (ก) อย่างเดียวคือปล่อยข้อ (ข) เป็นสถานะ "ไม่รู้"

## 3. ⚠️ ช่องว่างที่พบและบันทึกไว้ (ล็อกด้วยเทสต์ `GAP:` — ไม่ปล่อยเป็น "ไม่รู้")

### G1 — สถานะ "หลุด" เป็นเรื่องที่ **snapshot ผลัก** ไม่ใช่ **นาฬิกาผลัก**

`PresenceBoard.tsx:10` อ่าน `const now = Date.now()` **ตอน render** และคอมโพเนนต์
**ไม่มี timer ของตัวเอง** → การ์ดจะไม่พลิกเป็น "หลุด" ด้วยตัวเองแม้เวลาจะผ่านเกณฑ์ 90 วิไปแล้ว
มันพลิกก็ต่อเมื่อมี snapshot ของ `/presence` ตัวใหม่เข้ามาบังคับให้ re-render

**บนของจริงเกณฑ์ยังผ่าน** เพราะ HQ เครื่องที่ยังเปิดอยู่เขียน `/presence` ของตัวเองทุก 30 วิ
→ Firestore สะท้อน snapshot กลับมาเอง → การ์ดคำนวณ `now` ใหม่ → เครื่องที่เงียบพลิกเป็นหลุด
ภายในราว 90–120 วิ **กลไกนี้เป็นการพึ่งพาโดยบังเอิญ ไม่ได้เขียนไว้ว่าตั้งใจ**
→ เทสต์ D4 จึงล็อก invariant ที่รับน้ำหนักอยู่: `HEARTBEAT_MS * 2 <= ONLINE_THRESHOLD_MS`
(30_000 × 2 ≤ 90_000 ✅ — เผื่อพลาดไปหนึ่งจังหวะยังไม่ขึ้นหลุด)

ถ้าวันหนึ่งมีคนเอา `PresenceBoard` ไปแปะจอที่ไม่มี heartbeat จะ **ค้างเขียวถาวร**
ปิดช่องนี้ตรงๆ ต้องเพิ่ม tick เข้าไปใน `PresenceBoard` = **แก้คอมโพเนนต์ comms ซึ่ง Out of scope ห้ามแตะ**
→ ล็อกไว้ด้วยเทสต์ D3 ซึ่ง **ตั้งใจให้แดงวันที่มีคนแก้** (ให้ลบเทสต์แล้วมาอัปเดตบัญชี)

### G2 — HQ สองเครื่องที่ตั้ง booth ไว้คนละซุ้ม จะเห็นข้อความ **scope เจาะซุ้ม** ไม่เท่ากัน

`DashboardScreen.tsx:28` `hqBooth = loadDeviceConfig()?.booth ?? 'photo'` แล้วส่งเข้า
`CommsToast` → `visibleMessages(…, myBooth, …)` ตัดข้อความที่ `scope` ไม่ตรง booth ทิ้ง
→ HQ ที่ตั้งเป็น `photo` เห็น alert ของซุ้ม photo แต่ HQ ที่ตั้งเป็น `drinks` ไม่เห็น
ขัดกับ §4.1 `:98` "2 เครื่องเหมือนกันทุกปุ่ม" ในเชิงข้อมูลที่เห็น

**แต่วันนี้เอื้อมไม่ถึง**: ไม่มีที่ไหนในแอปส่งข้อความแบบ scope เจาะซุ้มเลย —
`AlertButtons.tsx:21` และ `BroadcastBar.tsx:17` **ใช้ `scope: 'all'` ทั้งคู่**
(เทสต์ E2 กวาดไฟล์จริงยืนยัน และเป็น spine ที่พิสูจน์ว่าตัวสแกนยังมองเห็นอะไรอยู่)
ปิดให้ถูกต้องต้องให้ HQ มองเห็นทุก scope = **แก้ `visibleMessages` = logic comms ซึ่ง Out of scope**

### G3 — HQ ไม่มี Export (.xlsx/PDF) ทั้งที่ §4.1 `:106` เรียกมันว่าของ "เดิม"

`:106` เขียนว่า *"Donation thermometer (ใหญ่) + **Export (.xlsx/PDF) เดิม**"*
คำว่า "เดิม" เป็น **ข้ออ้างที่ไม่จริง** — กวาดทั้ง `src/` ไม่มี `xlsx` / `createObjectURL` /
`download=` / `.pdf` เลยสักที่ และ `package.json` ก็ไม่มี dependency ไหนทำเรื่องนี้

**ไม่ทำให้เกณฑ์ข้อนี้ตก** เพราะสิ่งที่เกณฑ์ถามคือ "สองเครื่อง **เหมือนกัน**" ซึ่งจริง
(โค้ดชุดเดียวกัน ไม่มีสาขาแยกตามเครื่อง) — **สิ่งที่ขาด ขาดเท่ากันทั้งสองเครื่อง**
ทำให้มีจริงต้อง **เพิ่ม dependency ใหม่** ซึ่ง Out of scope ห้ามไว้ตรงตัว
→ ล็อกด้วยเทสต์ F1 ซึ่งจะแดงวันที่มีคนทำ Export (ตั้งใจให้แดง)

## 4. ขอบเขตของหลักฐาน (อ่านก่อนเชื่อ)

- `ordersRepo` / `expensesRepo` / `commsRepo` ถูก **mock ทั้งโมดูล**
  → **ไม่เคยต่อ Firestore จริง ไม่มี MacBook ไม่มี Windows เครื่องที่สอง ไม่เคยดึงปลั๊ก**
- คำว่า **"realtime"** พิสูจน์ได้แค่ว่า จอต่อ listener ไว้ และวาดใหม่จาก snapshot **โดยไม่ต้องรีเฟรช**
  (B2 ไปไกลกว่านั้นหนึ่งขั้น: ยืนยันว่าเป็น **DOM node ตัวเดิม** ที่เปลี่ยนค่า = อัปเดตสด ไม่ใช่ remount)
  **ไม่ได้จับเวลาจริงบนเน็ตจริง**
- jsdom ไม่รัน cascade ไม่ layout → ไม่มีเทสต์ไหนวัดพิกเซล
- **ข้อจำกัดของการจำลอง "สองเครื่อง" ในกล่องเดียว**: render สองครั้งอยู่ใน JS context เดียวกัน
  → mock ของ `getDeviceId` เป็นค่าตัวเดียวที่ mutate ได้ และ `DashboardScreen` อ่านค่านั้น
  **ทุกครั้งที่ render** → เครื่องที่เปิดก่อนจะ "เปลี่ยนชื่อ" ถ้ามันถูก re-render หลังเปิดเครื่องที่สอง
  → เทสต์ที่ assert เรื่อง **ตัวตนของเครื่อง** (A2, C5) assert **ก่อนมี snapshot ใดๆ เข้ามา**
  ส่วนเทสต์ที่กระทำหลัง emit กระทำกับ **เครื่องที่เปิดทีหลัง** ซึ่ง id ตรงอยู่แล้ว
  (บทเรียนต่อจากรอบ 0108 ที่ mock ค่าเดียวทั้งไฟล์ทำให้ "สองเครื่อง" กลายเป็นเครื่องเดียวเงียบๆ)
- ตรวจ isolation แล้ว: `grep -ci "@firebase\|GrpcConnection"` ใน log = **0** → ไฟล์นี้ไม่ยิง Firestore จริง

## 7. บทเรียนที่เอาไปใช้รอบหน้าได้

1. **เทสต์ "สองเครื่อง" ต้องผูก query กับ container ของแต่ละเครื่อง** (`within(container)`)
   ถ้าใช้ `screen` ที่กวาดทั้ง `document.body` จะเจอ testid ซ้ำแล้วพังทันที —
   และถ้าเผลอไปหยิบ instance เดียวมาเทียบกับตัวเอง เทสต์จะเขียวแบบไร้ความหมาย
2. **จำลอง "เครื่องที่ปิดไปแล้ว" ให้ถูก**: mock ของ `unsubscribe` ต้อง **ทำเครื่องหมายว่า sub ตายแล้ว**
   แล้ว helper ที่ยิง snapshot ต้องข้ามตัวที่ตาย ไม่งั้น "ปิดเครื่องแล้วยังรับข้อมูล" จะไม่มีวันถูกจับ
3. **`vi.useFakeTimers({ toFake: [...] })` เมื่อต้องคุม `Date.now` เอง** — fake timers เต็มรูปแบบ
   จะทับ `Date.now` ที่ spy ไว้ ทำให้ `clock` ที่เขียนเองไม่มีผล → ระบุเฉพาะ `setInterval`/`setTimeout`
4. **เทสต์ที่บอกว่า "อะไรบางอย่างไม่เกิดขึ้น" ต้องเปิดโอกาสให้มันเกิดก่อน** — D3 ฉบับแรกแค่เลื่อนนาฬิกา
   แล้ว assert ว่าไม่เปลี่ยน ซึ่ง **เขียวเสมอ** เพราะไม่มีอะไรกระตุ้น re-render อยู่แล้ว
   ฉบับที่ใช้จริงเดิน timer จริงด้วย → ถ้าวันหนึ่งมีคนใส่ tick เข้าไป เทสต์จะจับได้
5. **เทสต์ที่เทียบสองฝั่งซึ่งมาจากสูตรเดียวกัน ต้องปักค่าจริงไว้ด้วย** — ไม่งั้นแก้สูตรแล้วสองฝั่ง
   ขยับพร้อมกัน เขียวต่อไปทั้งที่ยอดเปลี่ยน (บทเรียนตระกูลเดียวกับ `expect([]).toEqual([])`)
