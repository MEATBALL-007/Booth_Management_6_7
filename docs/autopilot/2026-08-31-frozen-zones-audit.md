## 1. เกณฑ์นี้แยกเป็นสองครึ่ง และครึ่งเดียวที่เทสต์ได้

### ครึ่งแรก — "เทสต์ทั้งชุดเขียว + `npm run build` ผ่าน"

คือ Verify command ของโปรเจคตรงๆ **ไม่ได้เขียนเทสต์มายืนยันข้อนี้ เพราะมันวนเป็นวงกลม**
(เทสต์ที่ assert ว่าเทสต์ผ่าน พังพร้อมกับชุดที่มันอ้างถึงเสมอ) หลักฐานคือผลรันจริง:

```
npm test      →  48 ไฟล์ · 262 เทสต์ · ผ่านทั้งหมด
npm run build →  tsc -b ผ่าน · vite build 116 modules
                 PWA v1.3.0 generateSW · precache 5 entries (847.20 KiB)
                 dist/sw.js + dist/workbox-9c191d2f.js
```

⚠️ รันทั้งสองคำสั่งเสมอ — `npm test` เขียวไม่ได้แปลว่า build ผ่าน vitest ไม่ typecheck
แต่ `tsc -b` typecheck ไฟล์เทสต์ด้วย (รอบ `_0009` เจอ `TS6133` หลังเทสต์เขียวครบแล้ว)
รอบนี้ไฟล์ใหม่เป็น `.ts` ล้วนและ typecheck ผ่านตั้งแต่ครั้งแรก

### ครึ่งหลัง — "ไม่เปลี่ยน logic บัญชี/เมนู/comms"

นี่คือของจริง ทำเป็น **สวีปที่รันได้** ใน `src/frozenZones.audit.test.ts` (10 เทสต์)
ใช้ `git` เป็นผู้ตัดสิน เพราะเป็นแหล่งความจริงเดียวกับที่ reviewer จะใช้

**ฐานเปรียบเทียบคือ `git merge-base main HEAD` ไม่ใช่ปลายของ `main`**
ถ้าใช้ `git diff main` แบบสองจุด พอ `main` เดินหน้าไป commit ของ main เองจะถูกรายงาน
ว่า branch นี้ revert ทิ้ง — สวีปจะแดงโดยที่ branch ไม่ได้ทำอะไรผิดเลย

ชุดที่ตรวจ = `git diff --name-only <merge-base>` **บวก** `git ls-files --others --exclude-standard`
(ไฟล์ใหม่ที่ยังไม่ track ก็ต้องนับ — M3 พิสูจน์ว่าเส้นทางนี้ทำงานจริง)

## 2. โซนที่แช่แข็ง — ได้มาจากการ grep แนวคิด ไม่ใช่เดาจากชื่อโฟลเดอร์

```
git grep -l -iE 'happyHour|unitPrice|expectedCash|donation' -- src
git grep -l -E  'MENU|catalog' -- src
```

| โซน | ไฟล์ |
|---|---|
| บัญชี — ยอดขาย, PIN | `src/dashboard/metrics.ts`, `src/dashboard/pinStore.ts` |
| บัญชี — รายจ่าย | `src/expense/expensesRepo.ts` |
| บัญชี — คิดเงินบนออเดอร์ | `src/order/buildOrder.ts`, `cart.ts`, `promptpay.ts` |
| เมนู | `src/domain/catalog.ts`, `src/order/options.ts` |
| comms | `src/comms/{commsLogic,commsRepo,useHeartbeat,types}.ts` |
| โครงร่างร่วม | `src/domain/types.ts` |

`src/domain/types.ts` อยู่ในลิสต์เพราะเป็น **รูปร่างที่ฟิลด์เงินอาศัยอยู่** —
แก้ `unitPrice` ตรงนั้นคือแก้บัญชี โดยไม่ต้องแตะไฟล์ไหนข้างบนเลยสักไฟล์

บวกกฎไดเรกทอรี `^src/(comms|dashboard|expense)/[^/]+\.ts$` เพื่อจับ **ไฟล์ใหม่**
ที่ลิสต์ยังไม่รู้จัก

### ทำไม `.tsx` ในโฟลเดอร์เหล่านั้นถึง *ไม่* ถูกแช่แข็ง

เจตนา ไม่ใช่ความหลงลืม สเปกเขียนเองว่า "diff เฉพาะ presentation" และเกณฑ์กลุ่ม
`ui-overhaul` ที่จะทำต่อไป **จำเป็นต้อง** เปลี่ยนหน้าตาของหน้าบัญชี
ถ้าแช่แข็ง presentation ไว้ด้วย รอบหน้าจะเจอ tripwire ที่ไม่มีทางผ่าน แล้ว **ลบทั้งไฟล์ทิ้ง**
ซึ่งจะพาหลักประกันเรื่อง logic หายไปด้วย — เลือกกฎที่รอบหน้าอยู่ร่วมกับมันได้
(ตอนนี้ไฟล์ `.tsx` พวกนั้นก็ไม่ได้เปลี่ยนอยู่ดี P1 ปักไว้แล้ว)

## 3. สำมะโน — ไม่มี path ไหนอยู่ในสถานะ "ไม่รู้ว่าเปลี่ยนอะไร"

`classify()` เป็น **กฎเชิงโครงสร้าง** ไม่ใช่รายชื่อไฟล์ที่บังเอิญเปลี่ยน —
ถ้าเป็นรายชื่อ P1 จะกลายเป็นการเทียบลิสต์กับตัวมันเอง (tautology)

| หมวด | กฎ |
|---|---|
| `audit-test` | `^src/.*\.audit\.test\.tsx?$` |
| `src-test` | `^src/.*\.test\.tsx?$` |
| `production` | `^src/.*\.(ts\|tsx\|css)$` |
| `doc` | `AUTOPILOT/SUMMARY/CONTINUE_HERE.md` หรือ `docs/**.md` |
| `unknown` | ที่เหลือ → **C1 แดง** |

**ลำดับสำคัญ** — ไฟล์ audit ก็เป็น `.test.tsx` เหมือนกัน ถ้าเช็ค `src-test` ก่อน
ไฟล์ audit ทั้ง 9 จะถูกจัดผิดหมวด แล้ว P1 ยังเขียวอยู่ดี M8 ปักลำดับนี้ไว้

### ไฟล์ production ที่เปลี่ยน — ครบทั้งสี่ พร้อมเหตุผล

| ไฟล์ | ทำไมไม่ใช่ logic บัญชี/เมนู/comms |

## 5. ขอบเขตของหลักฐาน — อะไรที่ *ไม่* ได้พิสูจน์

- 🚨 **ไม่ได้พิสูจน์ "พฤติกรรม" ของบัญชี/เมนู/comms** พิสูจน์แค่ว่า **ซอร์สเหมือนเดิมทุกไบต์**
  ไฟล์ที่เหมือนเดิมยังเปลี่ยนพฤติกรรมได้ ถ้าของที่มัน import เปลี่ยนข้างใต้
  **ไม่ได้เดินตาม import closure** — เช่นถ้า `src/lib/firebase.ts` เปลี่ยน
  ผลจะไปถึง `expensesRepo` โดยไฟล์นี้ไม่รู้เรื่อง (`src/domain/types.ts` ถูกใส่ในลิสต์
  เพราะเป็นเส้นทางแบบนี้ที่ชัดที่สุด แต่ปิดได้เส้นเดียว ไม่ใช่ทุกเส้น)
- 🚨 **สวีป M เป็น heuristic ไม่ใช่ proof** มันแค่ grep บรรทัด diff หาคำที่เกี่ยวกับเงิน/เมนู
  คนที่แก้ logic บัญชีโดยไม่เผลอพิมพ์คำพวกนั้นเลย จะรอด **F2 ต่างหากคือ proof**
  M เป็นแค่ตาข่ายชั้นสองใต้สี่ไฟล์ที่ *ได้รับอนุญาต* ให้เปลี่ยน
- **ครึ่งแรกของเกณฑ์ไม่มีเทสต์รองรับ โดยตั้งใจ** — บันทึกผลรันไว้แทน (ข้อ 1)
  ถ้าอยากรู้ว่าวันนี้ยังจริงไหม ต้องรัน Verify command เอง ไฟล์นี้ตอบให้ไม่ได้
- ไฟล์ที่ถูก gitignore (`dist/`, `tsconfig.tsbuildinfo`) มองไม่เห็นทั้ง `git diff`
  และ `git ls-files --others --exclude-standard` — เป็น build output ไม่มีใคร import
- **สวีปนี้พูดถึง branch เทียบ branch point เท่านั้น** ไม่ได้พูดถึงว่าโค้ดบน `main` ถูกหรือผิด
