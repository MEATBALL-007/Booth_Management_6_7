# Display: จัดกึ่งกลาง + responsive + "เตรียมตัว" callout — audit

รอบ `auto/Booth_Management_6_7/2026-08-30_0039`

เกณฑ์: *"Display: จัดกึ่งกลางทุกจอ (responsive), 'เตรียมตัว' callout เด่น, skipped ไม่โชว์"*

## สรุป

**โค้ด production ถูกต้องอยู่แล้ว — ไม่ได้แก้อะไรใน `src/` เลย** สิ่งที่ขาดคือเทสต์
เขียนใหม่ 15 ตัวใน `src/displayCentering.audit.test.tsx` (237 เทสต์ทั้งชุด, build ผ่าน)

เกณฑ์นี้มี 3 ส่วน ไฟล์นี้พิสูจน์ 2 ส่วน ส่วนที่ 3 **ถูกพิสูจน์ไปแล้ว** ที่อื่น:

| ส่วน | พิสูจน์ที่ไหน |
|---|---|
| จัดกึ่งกลางทุกจอ (responsive) | ไฟล์นี้ — A0–A4, B1–B3 |
| "เตรียมตัว" callout เด่น | ไฟล์นี้ — C1–C7 |
| **skipped ไม่โชว์** | **`noShowRecall.audit.test.tsx` B1–B4 — อ้างอิง ไม่เขียนซ้ำ** |

`noShowRecall` B1 กวาด `document.body.textContent` ทั้งหน้า, B2 เคสมีแต่ skipped,
B3 skipped ที่เก่าที่สุดต้องไม่กลายเป็น next-up, B4 recall แล้วกลับมา (พิสูจน์ว่าเป็น
filter ไม่ใช่ blacklist) เขียนซ้ำที่นี่จะได้เทสต์เขียวเพิ่มโดยไม่ได้หลักฐานเพิ่ม

## ขอบเขตของหลักฐาน

🚨 **ไม่มีพิกเซลไหนถูกวัดเลยในไฟล์นี้** jsdom ไม่โหลด stylesheet ไม่ resolve คลาส Tailwind
ไม่คำนวณ layout และไม่มี viewport — `getBoundingClientRect()` คืนศูนย์ทุกตัว
**ไม่มีอะไรในไฟล์นี้บอกได้ว่าจอมันดู "กึ่งกลาง" จริงในหอประชุมโรงเรียน**

สิ่งที่เป็นข้อเท็จจริงตรวจได้จริงคือ **คลาสที่ประกาศบนแต่ละ element ของสาย ancestor**
และนั่นคือสิ่งเดียวที่ assert ก้าวจากตรงนั้นไปเป็น "มันกึ่งกลาง" อาศัยสมมติฐานว่า
Tailwind ปล่อยกฎ flexbox ตามที่เอกสารมันบอก — **สมมติ ไม่ได้พิสูจน์**

พูดตรงๆ มันคือ **รั้วกันการถดถอย**: จับได้ตอนการจัดกึ่งกลางถูก *ถอดออก* หรือมี
*flex box ที่ไม่จัดกึ่งกลางถูกแทรกกลางสาย* ซึ่งเป็นรูปแบบที่เกณฑ์ข้อนี้พังจริงๆ

เช่นเดียวกัน "responsive" พิสูจน์ว่า *`clamp()` / `md:` / `flex-wrap` ถูกประกาศ* ไม่ใช่
พฤติกรรมที่ 768px จริง และ "เด่น" พิสูจน์ว่า *ขนาดตัวอักษรที่ประกาศใหญ่กว่าจริง และ
color token คนละตัว* ไม่ใช่ความเด่นเชิงสายตา

## กฎแกน (axis rule) — หัวใจของไฟล์นี้

**การเช็คคลาสที่ root อย่างเดียวไม่พิสูจน์อะไร** และทิศทางเป็นตัวตัดสินว่า property ไหน
คุมแกนไหน — พลาดตรงนี้คือเทสต์กลายเป็นการโยนหัวก้อย:

- `flex-col` → แกนหลักตั้ง, **แกนนอนเป็น cross axis** → คุมด้วย `items-*`
- row → แกนหลักนอน → คุมด้วย `justify-*`

`items-center` จึงจัดกึ่งกลาง**แนวนอน**บน column แต่จัดกึ่งกลาง**แนวตั้ง**บน row
**A0 ปักกฎนี้ไว้กับ fixture ที่สร้างมือ** เพื่อไม่ให้ helper เสื่อมเงียบๆ เป็น "คืน true บ่อยๆ"

สายจริงจากเลขคิว serving ขึ้นไปถึง root มี **4 ชั้น และเปลี่ยนทิศกลางทาง**:
`['col', 'row', 'col', 'col']` — A2 ปักลำดับนี้ไว้ ทั้งสองสาขาของกฎจึงถูกใช้จริง

## `min-h-screen` เป็นตัวรับน้ำหนัก

`justify-center` ในกล่องที่สูงเท่าเนื้อหาตัวเอง **ไม่ได้จัดกึ่งกลางอะไรเลย**
ถอด `min-h-screen` ออก → "จัดกึ่งกลางแนวตั้ง" เป็นเท็จทันที ทั้งที่คลาสจัดกึ่งกลาง
ยังอยู่ครบทุกตัว และเทสต์แบบไร้เดียงสายังเขียว — M3 พิสูจน์แล้วว่า A1 จับได้

### พลาดตรงไหน และทำไม

- **M2, M5 → A4 แดงด้วย** ทั้งคู่พลาดด้วยเหตุผลเดียวกัน: A4 assert สาย serving ว่า
  **สะอาดก่อน** แล้วค่อยแทรกกล่องเสีย ฉะนั้นอะไรที่ทำให้สาย serving หรือ root พัง
  จะฆ่า A4 ไปด้วยเสมอ — **A4 เป็น canary ของทั้งสาย** ไม่ใช่แค่เทสต์ตัวแทรก
- **M13 → C6 แดงด้วย** เลือก `display.upNext` มาแทน ซึ่งบังเอิญเป็นสตริง `คิวถัดไป`
  ที่ C6 assert แบบ negative ไว้พอดี
- **M11 นอกไฟล์ทำนายผิด** ทำนายว่า `noShowRecall` B1–B3 จะแดง — **ไม่แดง และถูกแล้ว**
  เพราะ blacklist `!== 'skipped'` ก็ยังกัน skipped อยู่ดี สิ่งที่มันพังคือ order สถานะ
  `serving`/`done` รั่วเข้ามาในลิสต์ up-next ต่างหาก บทเรียน: **ต้องคิดว่า mutation
  ทำลาย property ไหน ไม่ใช่ว่ามัน "อยู่ใกล้" เทสต์ไหน**

## เทสต์ที่ไม่มี killer — ตั้งใจ

**A0 ไม่มี mutation ตัวไหนใน production ฆ่าได้เลย** เพราะมันไม่ได้ทดสอบ product —
มันปัก **ตัว checker เอง** ไว้กับ fixture ที่สร้างมือ (`div('flex items-center')` ฯลฯ)
ถ้า helper `centersHorizontally` ถูกแก้ให้เพี้ยน sweep A2/A3/A4 จะบอด **แต่ยังเขียว**
เพราะ `[].filter(อะไรก็ตาม)` ก็เป็น array ว่าง A0 คือสิ่งเดียวที่จับได้
(เทียบได้กับ E1 ของรอบ `_0004` — ปักคุณสมบัติของเครื่องมือ ไม่ใช่ของโค้ด)

14 จาก 15 ตัวมี killer จริง

## ⚠️ เทสต์ที่มี killer ตัวเดียว — ห้ามลบ

**A3** (M2), **B1** (M8), **B2** (M12), **C3** (M13), **C4** (M7), **C7** (M11)

และ **ห้ามลบ A0** ตามเหตุผลด้านบน — มันไม่มี killer เพราะมันเป็นคนละชั้นของหลักฐาน

## กับดักที่เจอระหว่างทาง

**กฎ "ทุก row ต้อง `flex-wrap`" กว้างเกินไป** ตอนแรกเขียน B3 ให้กวาด row ทั้งหมด
แล้วมันแดงใส่ **ป้าย LIVE** ซึ่งเป็น atom สองชิ้นที่ประกาศ `shrink-0` ไว้ตั้งใจ
ไม่ใช่บั๊ก — บั๊กจริงคือ row ที่ **จำนวนลูกโตตามข้อมูล** ฉะนั้น B3 กวาดเฉพาะ row
บนสาย ancestor ของเลขคิวที่ซ้ำได้ แล้ว **ปักป้าย LIVE ไว้ต่างหาก** ว่ายกเว้นเพราะ
มันประกาศ `shrink-0` เอง ไม่ใช่เพราะ sweep แกล้งมองไม่เห็น
