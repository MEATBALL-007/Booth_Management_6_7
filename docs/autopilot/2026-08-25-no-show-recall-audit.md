## 2. จุดที่ต้องตัดสิน — ตัดสินแล้ว

### 2.1 "หายจากจอลูกค้า" ตรวจที่ไหน

ตรวจที่ **`document.body.textContent` ทั้งก้อน** ไม่ใช่ที่ testid ที่รู้จัก
(`serving` / `next-up` / `upnext`) — เลขที่รั่วไปโผล่ในโซนที่ยังไม่มีใครตั้งชื่อ ก็ยังเป็นบั๊ก
ที่ลูกค้ามองเห็น เทสต์แบบไล่ testid จะมองไม่เห็นวันที่มีคนเพิ่มโซนใหม่

ทุกการกวาดแบบนี้ **มีคู่ spine เสมอ** ที่ยืนยันว่าการกวาดยัง**มองเห็น**เลขที่ควรอยู่
(`expect(all).toContain('A1')`) — ไม่งั้นมันคือ `expect([]).toEqual([])` ในหน้ากากใหม่
และ B4 เป็น spine ระดับพฤติกรรม: เรียกซ้ำแล้วเลขนั้น**กลับมาโชว์** → ตัวกรองเป็น *ตัวกรอง*
ไม่ใช่ blacklist ที่บังเอิญไม่เคยเรนเดอร์เลขนั้นเลย

⚠️ **กับดัก substring**: การกวาด `textContent` เทียบด้วย `toContain` → ถ้าเลือกเลขคิวที่เป็น
substring ของกันเอง (`A1` กับ `A11`) เทสต์จะโกหก ไฟล์นี้ใช้ `A1 A2 A3 A9` ซึ่งไม่มีตัวไหน
เป็น substring ของตัวอื่น **ใครแก้ fixture ต้องรักษาคุณสมบัตินี้ไว้**

### 2.2 "Display ประกาศ" พิสูจน์ยังไงให้ไม่ vacuous

ต้อง **กด 3 snapshot คร่อมกัน** (baseline serving → skipped → serving อีกครั้ง) ไม่ใช่ render ครั้งเดียว
เพราะ `useServingAlert` เปรียบเทียบ snapshot ปัจจุบันกับ snapshot ก่อนหน้า

**flash ต้อง assert ที่ root element ตรงๆ** — จุดเขียว LIVE (`DisplayScreen.tsx:40`) มี
`animate-pulse` **ติดถาวร** → เทสต์ที่ถามว่า "มีอะไรกระพริบไหม" จะเขียวเสมอ
D4 มีไว้เพื่อ**บันทึกกับดักนี้ให้เห็นกับตา**: มันยืนยันพร้อมกันว่า root **ไม่**กระพริบ
และว่า `container.querySelectorAll('.animate-pulse').length > 0` — สองบรรทัดนี้อยู่ด้วยกัน
เพื่อให้คนอ่านเห็นว่าทำไมวิธีค้นด้วย class ถึงใช้ไม่ได้

### 2.3 "ข้าม แล้วต้องไม่ประกาศ" — เทสต์ที่บอกว่าอะไรไม่เกิดขึ้น

false alert บนจอลูกค้าคือบั๊กที่คนดูเห็นทันที จึงล็อกไว้ (D3) แต่เทสต์ประเภทนี้
**ต้องเปิดโอกาสให้มันเกิดก่อน** — D3 ยิง snapshot ของการ ข้าม จริง (ซึ่งทำให้ effect ของ
`useServingAlert` **รันจริง** เพราะ serving key เปลี่ยน) แล้วค่อย assert ว่าเงียบ
และปิดท้ายด้วย spine: snapshot ถัดไปที่มีเลข**ใหม่จริง**เข้า serving ต้องทำให้ chime ดัง
→ ความเงียบในบรรทัดก่อนหน้าเป็นฝีมือของโค้ด ไม่ใช่ของ harness ที่ตายไปแล้ว

### 2.4 ทำไมต้องพิสูจน์ทั้งระดับ panel และระดับ Display

**นี่คือสิ่งที่ค้นพบและสำคัญที่สุดในรอบนี้** (M5 ใน §5)

`newlyAnnounced()` (`display/queueView.ts:18`) ถือว่าเลขที่**ไม่มีอยู่ใน snapshot ก่อนหน้า**
เป็นของใหม่เสมอ (`was === undefined`) → เวลา เรียกซ้ำ จอประกาศเพราะเลขนั้น
**กลับเข้ามาใน serving** ไม่ใช่เพราะ `recall()` เด้ง `announcedAt`

ผลคือ: **ลบ `announcedAt` ออกจาก `recall()` แล้วเทสต์ฝั่ง Display ยังเขียวหมด**
ยืนยันด้วย M5 จริงๆ แล้ว — D2 เขียว แดงแค่ A3 กับ D1 ซึ่งเป็นตัวที่ปัก**รูปร่างของ patch**
→ การพิสูจน์เกณฑ์ข้อนี้ที่ระดับ Display อย่างเดียว **อ่อนกว่าที่หน้าตามันดู**
ต้องมีคู่ที่ระดับ panel เสมอ (สอดคล้องกับบทเรียนรอบ 0031)

หมายเหตุ: **ไม่ใช่บั๊ก** — สเปก §4 เขียนเองว่าจอกระพริบเมื่อ (ก) มีเลขใหม่เข้า serving
**หรือ** (ข) `announcedAt` เพิ่มขึ้น การ เรียกซ้ำ เข้าเงื่อนไข (ก) อยู่แล้ว
`announcedAt` เป็นตัวรับน้ำหนักของเกณฑ์ **ประกาศซ้ำ** (`:23`) ซึ่งเป็นงานคนละรอบ

### 2.5 ขอบเขต: เกณฑ์นี้ไม่กินอะไร

- **Undo ของ ข้าม/เรียกซ้ำ** — เป็นเกณฑ์ Undo (`:21`) ซึ่งปิดไปแล้วรอบ 0053 **บน branch อื่น**
  บน branch นี้ `orderSnapshot()` ยังเป็นฉบับที่มีบั๊ก (คัดลอกเฉพาะ field ที่ `!== undefined`)
  **จงใจไม่แตะ** — ไม่ใช่งานรอบนี้ และจะชนกับงาน `_0053` ตอน merge
- **ประกาศซ้ำ** (`:23`) — ปุ่ม `ประกาศซ้ำ` มีอยู่และ `reannounce()` ทำงาน แต่เกณฑ์แยกต่างหาก
  รอบนี้แตะมันแค่ในฐานะ "ปุ่มที่ต้อง**ไม่**อยู่บนการ์ดพัก" (C3)
- **metrics** — ตรวจแล้วไม่ต้องแก้: `isRevenue()` (`dashboard/metrics.ts:23`) = `paid && !cancelled`
  → `skipped` นับเป็นรายได้ แต่ `doneCount` นับ `status === 'done'` เท่านั้น
  ตรงกับที่สเปก §2 เขียนเจตนาไว้เป๊ะ **ไม่ใช่ช่องว่าง** และอยู่นอกเกณฑ์ข้อนี้อยู่ดี

## 6. ขอบเขตของหลักฐาน (อ่านก่อนเชื่อ)

- `order/ordersRepo` และ `display/chime` ถูก **mock ทั้งโมดูล** → **ไม่เคยเขียน Firestore จริง
  และไม่เคยมีเสียงออกลำโพงจริง** "chime" พิสูจน์ได้แค่ว่า **`playChime` ถูกเรียก**
- jsdom **ไม่รัน cascade ไม่ layout** → "flash" พิสูจน์ได้แค่ว่า **root ประกาศคลาส `animate-pulse`**
  ไม่ใช่พิกเซลที่เปลี่ยนจริง · **ไม่มีเทสต์ไหนวัดพิกเซลหรือสีจริง**
- "หายจากจอลูกค้า" เป็น **ข้อเท็จจริงระดับ DOM** (สแกน `textContent` ทั้ง body) ซึ่งแข็งกว่า
  การเช็ค testid มาก แต่ก็ยังเป็น DOM ในกล่อง ไม่ใช่จอในหอประชุม
- **ไม่เคยเปิดเบราว์เซอร์จริง ไม่เคยกดปุ่มบน iPad จริง ไม่เคยลอง offline จริง**
- ยืนยันว่าไฟล์นี้ isolated จริง: รันทั้งชุดแล้ว `grep -ci "@firebase|GrpcConnection|
  Could not reach Cloud Firestore"` = **0** (เขียว ≠ isolated — ต้องเช็ค log ด้วย)
