## 2. บั๊กที่เจอ (ข้ออ้าง A)

grep `glow` เจอ 5 จุด แต่ **grep คำว่า glow อย่างเดียวมองไม่เห็นบั๊กที่ใหญ่กว่า** — glow ตัวที่สอง
เขียนเป็น arbitrary value ของ Tailwind (`shadow-[0_0_40px_rgba(...)]`) ซึ่งไม่มีคำว่า glow อยู่เลย

### บั๊ก 1 — การ์ด "เตรียมตัว" มีเงาเรืองแสงล้อมรอบ (`DisplayScreen.tsx:75`)

```
shadow-[0_0_40px_rgba(255,199,44,0.25)]
```

เงาเหลืองฟุ้ง 40px รอบ **การ์ด** ตรงกับข้อห้าม "ห้าม glow … การ์ด" ตรงตัวที่สุดในสเปก
สเปกที่มาทีหลัง (`2026-08-04-queue-pro-upgrade-design.md` §4) สั่งให้ callout **"เด่น"**
แต่ระบุวิธีไว้ว่า **"การ์ดเหลือง"** ไม่เคยพูดถึง glow — และ §5 ของสเปกนั้นเขียนกำกับไว้เองว่า
*"ธีม: Neon Clarity เดิม"* คือมอบอำนาจตัดสินกลับมาที่สเปกนี้ → **ผิดเกณฑ์**

### บั๊ก 2 — เลข "คิวถัดไป" เรืองแสงเท่าเลขที่กำลังทำ (`DisplayScreen.tsx:84`)

```
className="glow-y font-mono font-extrabold text-phantom-yellow text-[clamp(56px,10vw,140px)] …"
```

หลักฐาน 3 ชั้นว่าอันนี้ผิด ไม่ใช่แค่ "ตีความได้สองทาง":

1. §2 เขียนคำขยายไว้ตั้งใจ: *"เลขคิว**ที่กำลังทำ**"* ไม่ใช่ "เลขคิว" ลอยๆ
2. §5.3 สูตรของจอ Display เอง: *"NOW SERVING เลขใหญ่ glow … **UP NEXT pills สะอาด**"*
3. queue-pro §4 (glanceable): *"กำลังทำ = ส้ม**เรืองแสง** · ถัดไป = การ์ดเหลือง"*
   — คำว่า "เรืองแสง" ผูกกับ **กำลังทำ** เท่านั้น สัญญาณของ "ถัดไป" คือการ์ดเหลือง

และในทางใช้งานจริง glow สองที่พร้อมกัน **ทำลายเกณฑ์ glanceable ของอีกสเปกหนึ่ง**:
คนที่ยืนห่าง 5 เมตรเห็นเลขเรืองแสงสองเลข แยกไม่ออกว่าอันไหนคือ "ตอนนี้"

### แก้อย่างไร

ลบทั้งสองอย่างออก **ไม่แตะข้อความ ไม่แตะ logic ไม่แตะ testid** การ์ดยังเด่นด้วยของเดิมที่มีอยู่แล้ว:
`border-2 border-phantom-yellow/50` + `bg-phantom-yellow/10` + ขนาด `clamp(56px,10vw,140px)`
+ ไอคอน 👉 + ป้าย "เตรียมตัว" → ยังเป็นของที่ดังเป็นอันดับสองบนจอ แต่ไม่ยืม glow ของ "ตอนนี้" มาใช้

## 4. base +20% (ข้ออ้าง B) และคำถามเรื่อง radius/fontSize scale

`src/index.css:5` → `html { font-size: 120%; }` — root = 19.2px, utility ที่เป็น rem สเกลตามทั้งระบบ

แผนตั้งคำถามไว้ว่า สเปก §3 สั่งให้ tailwind extend **radius scale + fontSize scale (+20%)** ด้วย
ซึ่ง `tailwind.config.js` **ไม่มี** → เป็นช่องว่างจริงไหม? **คำตอบ: ไม่ใช่ช่องว่าง — เป็นวิธีที่ครอบคลุมกว่า**

ลองคูณดูจริง (Tailwind default × root 19.2px):

| utility | default | ที่ root 120% | รุ่นในสเปก §2 | ห่าง |
|---|---|---|---|---|
| `rounded-lg` | 0.5rem | **9.6px** | sm 10px | 0.4px |
| `rounded-xl` | 0.75rem | **14.4px** | md 14px | 0.4px |
| `rounded-2xl` | 1rem | **19.2px** | xl 20px | 0.8px |

บันได radius ที่โค้ดใช้อยู่ตกลงบนบันไดของสเปกอยู่แล้วโดยไม่ต้อง extend อะไรเลย
(`rounded-3xl` = 28.8px ที่ callout อยู่เหนือบันได — เป็นการ์ดขนาดจอใหญ่ ตั้งใจ)
และการคูณที่ root ยัง **สเกล padding/gap/ตัวหนังสือไปพร้อมกัน** ซึ่ง extend เฉพาะ `fontSize` ทำไม่ได้
→ บันทึกเป็นการตัดสินใจ ไม่ใช่การข้าม: config extend เพิ่มก็ไม่เปลี่ยนผลลัพธ์ แต่เพิ่มที่ให้ค่าดริฟต์ได้อีกที่

**ข้อยกเว้นที่จงใจไม่สเกลตาม root** (เขียนไว้กันคนอื่นเข้าใจผิดว่าเป็นบั๊ก):
`min-h-[44px]` (touch target เป็นข้อกำหนดทางกายภาพ ห้ามหด) และ `text-[clamp(...)]` บนจอ Display
(สเกลตาม **viewport** ไม่ใช่ตาม root — เป็นเจตนาของ §4)

เทสต์ล็อกไว้สองชั้น: มี `html{font-size:120%}` **บรรทัดเดียวในระบบ** (บรรทัดที่สองจะทับกันเงียบๆ)
และ **ห้ามมี `text-[NNpx]` ตายตัว** ที่ไหนเลย เพราะมันคือวิธีที่หน้าจอหนึ่งจะหลุดออกจาก +20% ได้จริง

## 6. วิธี assert (และทำไมถึงเลือกแบบนี้)

เทสต์ **อ่านไฟล์ source ทั้ง `src/` แล้วกวาด** ไม่ได้ render ทีละจอ เพราะเกณฑ์พูดว่า "**ทุกหน้า**"
ซึ่งรวมถึงหน้าที่ยังไม่มีในวันนี้ — เทสต์ที่ list ชื่อไฟล์ไว้จะมองไม่เห็นไฟล์ที่ 6 ที่ใครเพิ่มพรุ่งนี้
ทุกเทสต์ fail พร้อม **พิมพ์ `file:line` ของผู้ร้ายออกมาเอง** ไม่ต้องเดา

กับดักที่เจอตอนเขียน (แผนเตือนไว้ถูก): `\bglow-o\b` **แมตช์ข้างใน `shadow-glow-o` ด้วย**
เพราะ `-` เป็นขอบคำ → ถ้าไม่ใส่ negative lookbehind `(?<!shadow-)` บัญชีจะนับซ้ำและกลบของจริง

เทสต์ที่ต้องมีเพราะ "อยู่ในไฟล์ที่อนุญาต" ยังไม่พอ: **แต่ละบรรทัด glow ต้องถือหลักฐานของตัวเอง**
(บรรทัด `primary:` / กิ่ง `accent ?` / `data-testid="cart-total"`) มิฉะนั้นย้าย glow จากปุ่ม primary
ไปปุ่ม ghost ในไฟล์เดิม บัญชีก็ยังเขียว — พิสูจน์แล้วว่ากติกานี้จับได้จริง (break #3)

## 8. ⚠️ ขอบเขตของหลักฐาน — อ่านก่อนเชื่อว่าเขียว

- **ไม่มีเทสต์ไหนวัดพิกเซลหรือสีจริง** jsdom ไม่รัน cascade ไม่ layout
  ทั้งหมดพิสูจน์ระดับ **token ที่ประกาศไว้ + ตำแหน่งในไฟล์** พอจับ regression
  ("ใครเอา glow ไปแปะการ์ด") แต่**ไม่ได้**พิสูจน์ว่าจอจริงเรืองแสงถูกจุด — ต้องใช้เบราว์เซอร์จริง
- **"สม่ำเสมอ" ที่พิสูจน์ได้คือความสม่ำเสมอของ token ไม่ใช่ของสายตา** หน้าที่ใช้ `phantom-*` ครบ
  ยังจัด layout เละได้ — เกณฑ์ข้อถัดไป (iPad/จอใหญ่/touch target) ต่างหากที่ว่าด้วยเรื่องนั้น
- เทสต์อ่าน **source ไม่ใช่ผลลัพธ์ที่ build แล้ว** ถ้าใครสร้าง class ด้วยการต่อสตริงตอน runtime
  (เช่น `` `glow-${tone}` ``) การกวาดจะมองไม่เห็น — ตอนนี้ไม่มีใครทำแบบนั้นในโค้ด
