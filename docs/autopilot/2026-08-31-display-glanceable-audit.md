## 1. ข้อนี้มีบั๊กจริง — วัดก่อนแก้

ต่างจากรอบ `_0039` (Display centering) ที่โค้ด production ถูกอยู่แล้ว **รอบนี้แก้โค้ดจริง**
เขียนเทสต์ให้ครบก่อน แล้วรันกับโค้ดเดิม ได้ **แดง 8 จาก 15**:

```
× S1 × T1 × T2 × T3 × T4 × T5 × I3 × Z3        (green: S0 T0 I1 I2 Z0 Z1 Z2)
```

S1 พิมพ์ช่องว่างออกมาเป็น `file:line` ตรงๆ — นี่คือรายการที่วัดได้ ไม่ใช่ความเห็น:

```
DisplayScreen.tsx:37  {L(`booth.${booth}`).th} <span className="text-phantom-muted font-normal">· {...}.en}</span>
DisplayScreen.tsx:41  <span className="... text-sm md:text-base font-semibold ...">{L('display.live').en}</span>
DisplayScreen.tsx:47  🔔 {nowServing.th} · {nowServing.en}
DisplayScreen.tsx:51  {L('display.noQueue').th} · {L('display.noQueue').en}
DisplayScreen.tsx:79  {L('display.next').en} · {L('display.getReady').en}
DisplayScreen.tsx:94  {L('display.upNext').th} · {L('display.upNext').en}
```

**ช่องว่างมีสองแบบ:**

1. **ไทยกับอังกฤษเป็น "เพื่อน" ไม่ใช่ "หลัก/รอง"** — บรรทัด 47, 51, 94 เรนเดอร์ทั้งสองภาษา
   อยู่ใน **element เดียวกัน** ขนาดเท่ากัน น้ำหนักเท่ากัน สีเดียวกัน
   (`🔔 กำลังทำ · Now Serving`) เกณฑ์บอก "ไทยเด่น อังกฤษรอง" — สามจุดนี้ไม่มีอะไรเด่นกว่าอะไรเลย
   บรรทัด 37 (header) มีความต่างอยู่บ้าง (`font-normal` + `text-phantom-muted`) แต่ **ขนาดเท่ากัน**

2. **🚨 `LIVE` เป็นอังกฤษล้วน** — บรรทัด 41 เรนเดอร์ `.en` เดี่ยวๆ
   ทั้งที่ `display.live` มี `th: 'สด'` อยู่ในตารางมาตลอด
   แผนรอบก่อนเดาไว้แล้วว่าอาจเป็นช่องว่างข้อแรก และให้ตัดสินว่าเป็นบั๊กหรือยอมรับได้
   **ตัดสินว่าเป็นบั๊ก** — จุดเขียว pulse สื่อ "กำลังทำงานอยู่" ได้ก็จริง แต่คำว่า `LIVE` ที่อยู่ข้างๆ
   ไม่ใช่ "อังกฤษรอง" มันคือ **อังกฤษเดี่ยว** ซึ่งเป็นสิ่งที่เกณฑ์ห้ามตรงๆ
   แก้ให้เป็น `สด · LIVE` (ใช้ label ที่มีอยู่แล้ว ไม่ได้เพิ่ม string ใหม่)

## 2. วิธีแก้ — `<En>` ตัวเดียว และทำไมต้องเป็น `em`

```tsx
function En({ children }: { children: ReactNode }) {
  return <span className="font-kanit text-[0.7em] font-normal opacity-70">{children}</span>
}
```

ทุก `.en` บนจอลูกค้าเดินผ่านตัวนี้ตัวเดียว

**ทำไมไม่ใช้ named step (`text-sm md:text-base`) แบบที่ callout เคยใช้:**
หัวข้อไทยที่มันไปเกาะ **เปลี่ยนขนาดที่ `md:`** (`text-3xl md:text-5xl`, `text-2xl md:text-3xl`, …)
ถ้าอังกฤษเป็น named step มันต้องประกาศทับเองทุก breakpoint และ **ถ้าลืม `md:` ไปตัวเดียว
กฎ "ไทยเด่น" จะพลิกกลับด้านเฉพาะที่ความกว้างเดียว** ซึ่งเทสต์ที่ดูจอเดียวไม่มีวันเห็น
`em` เล็กกว่ากล่องที่มันอยู่ **ทุกความกว้าง โดยโครงสร้าง** — นี่คือสิ่งที่ทำให้
"ไทยเด่น อังกฤษรอง" เป็น **กฎเดียวที่สวีปได้** แทนที่จะเป็นข้อยกเว้นหกอัน

`0.7` ไม่ได้คิดขึ้นเอง — เป็นอัตราส่วนที่ callout `เตรียมตัว` ใช้อยู่แล้ว
(`text-sm` ในกล่อง `text-xl` = 14/20) แค่ขยายให้ครบทุกจุด

**สิ่งที่แก้เพิ่มอีกสองอย่าง (เล็ก แต่จำเป็นให้กฎเป็นกฎ):**
- `ยังไม่มีคิว` `<p>` ไม่เคยประกาศน้ำหนักเลย → ใส่ `font-semibold` ให้เท่าหัวข้ออื่น
  (ไม่งั้น "ไทยหนากว่าอังกฤษ" เป็นเท็จที่จุดนั้น เพราะไทยก็ `font-normal` เหมือนกัน)
- badge `LIVE` ขยับจาก `text-sm md:text-base` → `text-base md:text-lg`
  เพราะ `สด` ที่ 14px แล้ว `LIVE` เหลือ 9.8px เล็กเกินอ่าน

**ไม่ได้แตะ**: `labels.ts` (ใช้ของเดิมทั้งหมด), `QueueNumber.tsx`, logic ใดๆ

## 3. ขอบเขตของหลักฐาน — อ่านก่อนเชื่อ

🚨 **ไม่มีพิกเซลไหนถูกวัด และไม่มีฟอนต์ไหนถูกโหลด**
jsdom ไม่แปล Tailwind class ไม่คำนวณ layout ไม่มี viewport `getBoundingClientRect()` คืนศูนย์หมด
**ไม่มีอะไรในไฟล์นี้บอกได้ว่าจออ่านออกจากท้ายห้องโถง**

สิ่งที่เป็นข้อเท็จจริงตรวจได้คือ **class ที่ประกาศบน element** และนั่นคือสิ่งเดียวที่ assert
ก้าวไปเป็นข้อสรุปเชิงสายตาต้องอาศัยสมมติฐานสองข้อ ซึ่ง **สมมติ ไม่ได้พิสูจน์**:
- Tailwind ปล่อย type scale ตามเอกสาร (`text-2xl` = 24px, `text-[0.7em]` = 0.7 เท่าของที่สืบทอดมา)
- ตัวหนังสือที่เล็กกว่า บางกว่า จางกว่า **อ่านแล้วรู้สึกว่าเป็นของรอง** สำหรับคน

**"glanceable" เองวัดใน jsdom ไม่ได้เลย** สิ่งที่วัดได้และเป็นหัวใจของไฟล์นี้คือ property
ที่อ่อนกว่าแต่จริง: **ทุกความหมายบนจอถูกพาโดยอย่างอื่นที่ไม่ใช่คำภาษาอังกฤษ**
— คำไทย, emoji, token สี, หรือขนาด (เทสต์ `I3` พูดข้อนี้ตรงที่สุด: ลบ wrapper รองทิ้งทั้งหมด
แล้วบนจอต้อง **ไม่เหลือคำ Latin สักคำ** แต่ยังครบทุกโซน)

**ข้อมูลออเดอร์อยู่นอกขอบเขตโดยโครงสร้าง** — sweep หา "อังกฤษ" ด้วย *สคริปต์*
(`/[A-Za-z]{2,}/` ใน own text) ทำได้เพราะ fixture ทุกตัวตั้งใจไม่มีคำ Latin
(ชื่อเมนูเป็นไทย, เลขคิว `A1` มีตัวอักษรตัวเดียว) **ถ้าเมนูจริงชื่อภาษาอังกฤษ ไฟล์นี้จับไม่ได้
และไม่ได้อ้างว่าจับได้**

### ตัวที่ทำนายพลาด (M8) — และมันเจอเทสต์อ่อนจริง

ทำนายว่า T5 จะแดง เพราะ T5 คือเทสต์ "ไม่มีโซนไหนเป็นอังกฤษล้วน" แต่มันเขียว

สาเหตุ: T5 เขียนว่า `THAI.test(el.parentElement.textContent)` — **`textContent` คือข้อความของ
subtree ทั้งก้อน** ทั้งจอเต็มไปด้วยภาษาไทยอยู่แล้ว คำถามนี้จึงตอบตัวเองเสมอ
T2 ใช้ `ownText` (เฉพาะ text node ลูกตรง) จึงจับได้ ส่วน T5 ไม่จับ

**นี่คือบทเรียนเดิมที่เขียนไว้ในบันทึกรอบก่อนกัดตัวเอง**: *"ถามว่า mutation ทำลาย property ไหน
ไม่ใช่ว่ามันอยู่ใกล้เทสต์ไหน"* — ทำนายว่า T5 แดงเพราะ **หัวข้อของ T5 ตรงกับ mutation**
โดยไม่ได้กลับไปอ่านว่ามันใช้ accessor ตัวไหน

แก้ T5 ให้ใช้ `ownText(el.parentElement)` — เข้มกว่า T2 ด้วยซ้ำ (T2 ยอมให้ไทยอยู่ ancestor ไกลๆ
แล้วไปตรวจ *สไตล์* ของมัน · T5 บังคับว่าไทยต้องอยู่ **element เดียวกัน ติดกับอังกฤษ**
ซึ่งคือนิยามของ "คู่สองภาษา" จริงๆ) รันซ้ำ M8 → แดง 7 ตามที่ทำนาย
และ M1 ที่รันไปแล้วต้องรันซ้ำด้วย → กลายเป็นแดง 8 (T5 เพิ่มเข้ามา)

**สรุปคะแนน: 16 mutation · ทำนายตรง 15 · พลาด 1 · ตัวที่พลาดเจอ assertion อ่อนจริง แก้แล้ว**

## 5. เทสต์ตัวไหนห้ามลบ และทำไม

### ⚠️ มี killer ตัวเดียว — ลบแล้วช่องว่างนั้นไม่มีใครเฝ้าเลย

| เทสต์ | killer เดียว | ถ้าลบแล้วอะไรหลุด |
|---|---|---|
| `I1` | M9 | ลบ 🔔 / 👉 ออกจากจอแล้วไม่มีใครรู้ (I3 จับได้ด้วย แต่ I3 เป็นเทสต์รวม) |
| `Z1` | M7 | เลขคิวเล็กกว่า callout ได้โดยเทสต์เขียวหมด |

### ⚠️ ไม่มี production mutation ตัวไหนฆ่าได้เลย — **ตั้งใจ** ห้ามลบเด็ดขาด

`S0` `T0` `Z0` ปัก **ตัว checker เอง** ไว้กับ fixture ที่สร้างมือ ไม่ได้ปักตัวโปรดักต์
เหตุผลเดียวกับ `A0` ในรอบ `_0039`: **sweep ที่บอดแล้วยังเขียว** เพราะ
`[].filter(อะไรก็ได้)` ก็เป็น array ว่างเหมือนกัน

พิสูจน์แล้วด้วย M14/M15/M16 ว่าถ้า helper เพี้ยน:
- M14 (`enRegions` กลืนทั้งไฟล์) → **S1 เขียว** ทั้งที่ fence ไม่เหลืออะไร มีแต่ S0 ที่จับได้
- M15 (`subordinate` อ่อนลง) → T1/T5/I3 **เขียวหมด** มี T0 กับ T4 ที่จับได้
- M16 (`largestNamedSize` ไม่ตัด `md:`) → มี Z0 กับ Z2 ที่จับได้

📌 `T4` เป็น **canary ของทั้งกฎ** — มัน assert baseline สะอาดก่อนแล้วค่อยแทรก span เสีย
จึงตายไปกับทุก mutation ที่ทำให้จอจริงผิดกฎ (M1–M5, M8) **และ** กับ helper ที่อ่อนลง (M15)
ถ้าเห็น T4 แดงอย่าเพิ่งดูที่ตัวมัน ให้ดูว่าอะไรทำ baseline พัง

## 6. สิ่งที่ **ไม่ได้** ทำ

- **ไม่ได้แตะจออื่น** — เกณฑ์ระบุ "มองแวบเดียว" ซึ่งในสเปกหมายถึงจอลูกค้า (Display)
  `OrderStation` / `QueuePanel` / `DashboardScreen` ยังมีคู่สองภาษาแบบเดิมอยู่
  ถ้าจะขยายกฎนี้ทั้งแอป **นั่นคือเกณฑ์ "ทุกหน้าเป็นสไตล์ Neon Clarity สม่ำเสมอ"** คนละข้อ
  `BiLabel.tsx` (`src/i18n/BiLabel.tsx`) มี pattern คล้ายกันอยู่แล้ว (`text-xs opacity-70`)
  แต่ใช้ named step ไม่ใช่ `em` — **จุดเริ่มที่ดีถ้าจะทำข้อนั้น**
- **ไม่ได้พิสูจน์ว่าอ่านออกจริงบนจอจริง** ดูหัวข้อ 3
- **ไม่ได้กวาดชื่อเมนู** ถ้าเมนูชื่ออังกฤษ sweep นี้จับไม่ได้ (fixture เป็นไทยล้วนโดยตั้งใจ)
- ส่วน **ขนาด** อ้างอิง `displayCentering.audit.test.tsx` B1/C5 ไม่เขียนซ้ำ
  ที่เพิ่มมาคือความสัมพันธ์ที่ B1/C5 ไม่ได้ครอบ: **เลขคิว > callout ทุกพารามิเตอร์ของ clamp พร้อมกัน**
  (Z1) และ **เลขคิว > หัวข้อที่ใหญ่ที่สุดบนจอ** (Z2 ปักไว้ที่ `md:text-5xl` = 48px)
